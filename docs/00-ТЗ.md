## 1. Предмет, цели и границы

### 1.1 Цель
Создать браузерное приложение, открывающееся как **Telegram Mini App**, которое **визуально и функционально повторяет** исходное Android-приложение «Case Simulator» 1:1: те же экраны, названия, механики, анимации, звуки, предметы, кейсы, мини-игры, экономика, магазин и социальные функции. Дополнительно — **реальный онлайн** (без ботов), **рабочие платежи в Telegram Stars** и production-готовая инфраструктура.

### 1.2 Что входит
- Перенос **всего** функционала, наблюдаемого на видео и восстановленного из APK (перечень в разделе 6).
- Серверная (авторитетная) экономика: баланс, инвентарь, дропы, ставки, выдача наград.
- Многопользовательские режимы: чат, друзья, подарки, рефералы, PvP-битвы кейсов, общий джекпот и общие раунды Crash.
- Магазин на Stars: косметика + отдельные бусты (решение заказчика, раздел 4).
- Полный комплект документации и чистый монорепозиторий.

### 1.3 Что НЕ входит (жёсткие границы)
- ❌ Вывод реальных денег, вывод/обмен/передача скинов, P2P-маркет, привязка к Steam.
- ❌ Любые платежи кроме `XTR` внутри Telegram (другие валюты, крипта, сторонние провайдеры, внешние ссылки на оплату).
- ❌ Продажа внутриигровой валюты за звёзды напрямую (решение заказчика — гибридная модель).
- ❌ Влияние платных бустов на вероятность дропа / исход раунда.
- ❌ AdMob / Google Play Billing / Google Play Games / FCM / Play Integrity — заменяются (раздел 7).
- ❌ Нативные Android-разрешения, фоновые сервисы, push через FCM.
- ❌ Реальная азартная игра; продукт позиционируется как **симулятор 18+**.

### 1.4 Ключевой принцип
**Клиент ничего не решает.** Любое изменение баланса, инвентаря, результата дропа или ставки вычисляется и фиксируется сервером в одной транзакции. Клиент только отображает полученный результат и проигрывает анимацию.

### 2.4 Что восстановлено не полностью (требует решения)
1. **Точные веса дропа** по редкостям и конкретным предметам внутри каждого кейса — в бинарнике хранятся таблицами Dart AOT, однозначно не распарсены. **Решение:** взять официальные вероятности CS2 (Mil-Spec 79.92 %, Restricted 15.98 %, Classified 3.20 %, Covert 0.64 %, ★/Gloves 0.26 %) и зафиксировать их в `08-game-logic.md` как эталон, с возможностью правки админом.
2. **XP-кривая и пороги уровней 1..26+**, точная формула «МАКС. СТАВКА», RTP каждой мини-игры — восстанавливаются частично из строк и кадров; финализируются на этапе дизайн-фриза (вопрос Q-07).
3. **Точные цены IAP в EUR** — на видео видны €3.99 / €4.99 / €6.99 для косметики; полный прайс-лист в APK не найден. Для Stars вводится собственный прайс (раздел 14).
4. **Полный каталог ~15 000 изображений скинов** — в APK лежат только 30, остальные грузятся с CDN по предсказуемым путям. Требуется выгрузка/копирование CDN в свой Storage (раздел 18).
5. На видео дважды появляется системный оверлей стороннего приложения **Husk / Enable JIT** (02:20, 07:20) и чёрный экран загрузки (04:40) — **это артефакты записи/сайдлоада, не часть продукта**, в реплику не переносятся. Зафиксировано в `12-bugs-and-fixes.md`.

## 3. Термины

| Термин | Значение |
|---|---|
| **TMA** | Telegram Mini App |
| **XTR** | Telegram Stars, валюта инвойса |
| **initData** | подписанная Telegram строка авторизации; валидируется только на сервере |
| **Кейс / контейнер** | виртуальный ящик с предметом; открывается за виртуальные `$` + «ключ» |
| **Ролл** | один серверный результат открытия/ставки, записанный в `rolls` |
| **RTP** | return-to-player, доля возвращённой виртуальной валюты |
| **Provably fair** | commit–reveal: `sha256(server_seed)` публикуется до раунда, сид раскрывается после |
| **Wear / float** | FN / MW / FT / WW / BS + числовой float 0..1 |
| **StatTrak™ (ST)** | счётчик убийств, множитель цены ×2.0 |
| **Редкость** | Consumer, Industrial, Mil-Spec, Restricted, Classified, Covert, ★ Exceedingly Rare |
| ** Entitlement** | выданное пользователю право (буст/косметика), запись в `entitlements` |
| **Сейв** | состояние игрока; в оригинале локальный `cs2sim.db`, у нас — Postgres |

## 5. Общие требования

- **G-01** Приложение открывается по кнопке/Main Mini App бота и по deep link `https://t.me/<bot>?startapp=<payload>`, работает в iOS/Android/Telegram Desktop/Telegram Web.
- **G-02** Первый вызов `WebApp.ready()` и `expand()` — сразу после загрузки критического UI; заголовок/фон/нижняя панель красятся через `setHeaderColor`/`setBackgroundColor`/`setBottomBarColor`.
- **G-03** Все пользовательские данные привязаны к `telegram_user_id` из **провалидированного** `initData`; `initDataUnsafe` используется только для отображения имени/аватара.
- **G-04** Любое денежное/предметное изменение — атомарная серверная транзакция с `idempotency_key`.
- **G-05** Приложение обязано корректно работать при потере сети: показывать `common.noInternet.*`, не списывать средства дважды, восстанавливать состояние с сервера при реконнекте.
- **G-06** Явный дисклеймер 18+ на онбординге, в описании бота, в `/terms`: «Симулятор. Реальные деньги не используются. Виртуальные предметы не выводятся, не обмениваются и не имеют денежной стоимости. Не является азартной игрой».
- **G-07** Вероятности дропа и RTP игр раскрываются в UI (раздел «Как это работает»).
- **G-08** Все суммы внутри игры — виртуальные `$` с префиксом `$`, два знака, разделитель — точка. Реальные суммы (звёзды) показываются как `★ N` / `N XTR`.
- **G-09** Поддержка Telegram-темы: CSS-переменные `var(--tg-theme-*)`, `colorScheme`, `safeAreaInset*`, `contentSafeAreaInset*`, `--tg-viewport-stable-height`.
- **G-10** Все анимации — на `transform`/`opacity` (без layout-reflow), целевые 60 fps; на слабых устройствах — автоматическое снижение качества (уменьшение частиц, отключение блюра).
- **G-11** Тактильный отклик `HapticFeedback` на открытие, выигрыш, ошибку, выбор предмета.
- **G-12** `BackButton` Telegram синхронизирован с внутренним роутингом; `enableClosingConfirmation()` включается во время незавершённого раунда/открытия.
- **G-13** Никаких внешних платёжных ссылок, iframe оплаты, крипты, фиата внутри TMA.

## 6. Функциональные требования

> Формат: `FR-xx` — обязательный пункт. Полные тексты, статусы и крайние случаи — в профильных документах.

### FR-01 · Авторизация и онбординг
1. При старте клиент читает `window.Telegram.WebApp.initData`, отправляет его на `POST /auth/telegram` в заголовке `Authorization: tma <initData>` (не в URL, не в логи).
2. Сервер проверяет HMAC-SHA256, `auth_date` (TTL ≤ 3600 с) и anti-replay по `query_id`; выпускает ES256-JWT (Supabase JWT Signing Keys) с `app_metadata.telegram_user_id`.
3. Создаётся `users` + `wallets` со стартовым балансом, стартовый агент, реферальный код вида `ANRS37`, стартовый набор кейсов/заданий.
4. Онбординг: туториал по открытию кейса, контракт «Обучение», согласие с офертой и 18+ **до** первой покупки.
5. `start_param` обрабатывается: реферальный код, приглашение в битву, подарок, промо.

### FR-02 · Шелл и навигация (1:1)
- Верхняя панель: аватар агента + бейдж уровня (`1`), справа баланс зелёным (`$ 11.74`); на вложенных экранах — стрелка «назад».
- Нижняя навигация, **5 вкладок**: `Кейсы` · `Инвентарь` · `Контракты` (красная точка-индикатор наград) · `Игры` · `Магазин`.
- Вкладки верхнего уровня внутри «Кейсы»: `КЕЙСЫ` · `ЧЁРНЫЙ РЫНОК` · `КАПСУЛЫ` + иконка друзей.
- Экран «УЛУЧШЕНИЯ» (5 треков), экран «Профиль» с вкладками `ПРОФИЛЬ` · `ДРУЗЬЯ` · `КЕЙСЫ` · `БИТВЫ`.
- Все переходы, жесты «назад», «tap to continue / tap to skip» — как на видео.

### FR-03 · Каталог кейсов
- 241 кейс/капсула из `reference/case-names.txt`, сгруппированные: **Cases**, **Capsules**, **Souvenir**, **Black Market**.
- Сетка 3 колонки: изображение, цена зелёным, градиентная оранжевая подчёркивающая линия, название латиницей.
- Цены берутся из `prices.json` (`"Kilowatt Case": {"price": 0.11}` и т.п.), «ключ + контейнер» = цена кейса + цена ключа.
- Блокировка по уровню (`cases.opening.lockedLevel`), бейджи `ГОТОВО` / `ЗАПОЛНЕНО` / `БЕСПЛАТНО` / `СНАБЖЕНИЕ` / `ХРАНИЛИЩЕ`, сортировка и поиск.
- «Чёрный рынок»: кастомные кейсы (`Covert Case`, `Hell Case`, `Military Case`, `Lucky Trade`, `Sniper Replie`, `Bitfix Postcall`, `Golden Idol`, `Wild Kingdom`, `Phantom`, …), цены красным, кнопка `ЗАБРАТЬ`, кулдаун, `Кейсы чёрного рынка обновились`.

### FR-04 · Открытие кейса (рулетка) — визуальная точность критична
1. Экран: горизонтальная лента предметов, оранжевый треугольник-указатель сверху по центру, цветная линия редкости под лентой, карточка выпавшего предмета.
2. Заголовок `СОДЕРЖИТ ОДНО ИЗ СЛЕДУЮЩЕГО:` + превью содержимого с ценами и процентами, блок `ВОЗМОЖНЫЕ НОЖИ` / `ВОЗМОЖНЫЕ ПЕРЧАТКИ`.
3. Кнопка `ОТКРЫТЬ КОНТЕЙНЕР` (серая/зелёная), подпись `Использовать ключ + контейнер: $2.61`.
4. Тумблеры `АВТООТКРЫТИЕ`, `АВТОВЫБОР`, шестерёнка; счётчик `ОТКРЫТЬ [1][2][3][5][6] КЕЙС`.
5. Анимация: лента 60 fps с easing, звук `csgo_ui_crate_item_scroll.wav`, тик при прохождении предмета, финальный `item_drop*.wav` по редкости; «tap to skip» пропускает анимацию, но результат уже зафиксирован сервером.
6. Результат: `ОСТАВИТЬ` / `ПРОДАТЬ`, цена, редкость, float, StatTrak™, `3D-ВИД ПРЕДМЕТОВ`.
7. Прерывание/потеря сети: состояние восстанавливается по `idempotency_key`, ролл не теряется (`cases.opening.interruptedOpening`).

### FR-05 · Режимы открытия
- `ОТКРЫТЬ 1 / 2 / 3 / 5 / 6 КЕЙС` (multi-open), `АВТО-ВЫБОР`, `АВТО-ОТКРЫТИЕ`, `БЫСТРОЕ ОТКРЫТИЕ`, `АВТО-ПРОДАЖА МУСОРА`.
- **МАССОВОЕ ОТКРЫТИЕ**: 200 → 1000 кейсов за раз (`massOpenOverdrive`), предпросмотр, `ПРОДАТЬ ВСЁ`, `ВСЕГО`, `РАСПАКОВАНО`, пропуск анимации.
- **АВТООТКРЫВАТЕЛЬ**: «Открывает один из любимых кейсов, пока тебя нет», интервал 5 мин, 5 слотов, `ЗАПОЛНЕНО`, `Открыто кейсов: 147`, `Прибыль $20.68`, авто-продажа за 65 % стоимости, офлайн-накопление с серверным временем, `claim`.

### FR-06 · Дроп, редкости, float, цены
- Редкости: Consumer → Industrial → Mil-Spec → Restricted → Classified → Covert → ★ (ножи/перчатки), с фиксированными цветами (раздел 16).
- Wear: `FN / MW / FT / WW / BS`, числовой float из диапазона предмета; StatTrak™ с шансом и ×2.0 к цене.
- Цена = `prices.json[item][wear]`, для стикеров/пакетов — `price`, для ST — ×`stattrakMultiplier`.
- Итог дропа, вес, сид и nonce пишутся в `rolls` до отправки клиенту.

### FR-07 · Инвентарь
- Поиск `Поиск среди N предметов`, фильтры `Цена / Редкость / Флоат / A–Z / Тип`, переключатель сетка/список, чипы выбранных фильтров, `Сбросить / Готово`.
- Слайдер «Макс. цена», статус `Открыто / В игре`, сортировка.
- Карточка: изображение, бейдж `ST`, wear, float, цена зелёным, цветная полоса редкости, имя.
- Лимит слотов = «ХРАНИЛИЩА»; при переполнении — `Освободите место…`.
- Действия: продать, массовая продажа, положить в хранилище, снять наклейку (`stickerRemover`), выбрать для ставки/апгрейда/обмена.

### FR-08 · Продажа
- Одиночная `ПРОДАТЬ $X`, **МАССОВАЯ ПРОДАЖА**: «Продавайте предметы стоимостью до выбранной суммы», степпер `до $1`, `ВЫБРАНО 56 шт.`, `ИТОГО $5.54`, сетка превью, зелёная кнопка `ПРОДАТЬ $5.54`.
- Все продажи идут через RPC, ledger `transactions`, курс фиксируется на момент продажи.

### FR-09 · Хранилище (Vault)

### FR-10 · Терминал / UP-Link / чат

### FR-16 · Джекпот и Crash (общие онлайн-раунды)

## 9. Стек и обоснование

> Полное обоснование, версии и альтернативы — [`04-architecture.md`](04-architecture.md) и [`decisions/ADR-001-stack.md`](decisions/ADR-001-stack.md).

| Слой | Выбор | Почему |
|---|---|---|
| Фронтенд | **Vite + React 19 + TypeScript + Tailwind CSS 4 + Zustand + TanStack Query + Motion (Framer Motion)** | Чистый SPA, SSR не нужен в webview; минимальный бандл; декларативные 60fps-анимации; кэш каталога и оффлайн; Telegram CSS-переменные через Tailwind |

| TMA SDK | `@telegram-apps/sdk` + `telegram-web-app.js` в `<head>` | Типизированный доступ к WebApp, версионирование методов |
| Бэкенд | **Node.js 22 LTS + TypeScript + Hono + grammY** на **Railway** | Долгоживущий процесс для вебхуков/воркеров/Realtime-координации, нет 2-секундного CPU-лимита Edge Functions |
| БД | **Supabase PostgreSQL** + RLS + RPC (`SECURITY DEFINER`) + Realtime Broadcast + Storage + `pg_cron` | Атомарные ставки через `SELECT … FOR UPDATE`, идемпотентность, серверный RNG, online-события, крон заданий |
| Авторизация | `initData` → HMAC → собственный **ES256 JWT** (Supabase JWT Signing Keys) → RLS по `app_metadata.telegram_user_id` | `signInWithIdToken` не принимает сырой `initData`; JWT Signing Keys — рекомендованный путь |
| Платежи | **Telegram Stars `XTR`**, `createInvoiceLink` + `WebApp.openInvoice`, webhook бота | Единственный легальный способ продавать цифровые товары в Telegram |
| Хранение картинок | Supabase Storage (публичный бакет) + CDN / Cloudflare Pages для статического SPA | 15k+ изображений, immutable-cache |
| Монорепо | **pnpm workspaces + Turborepo**: `apps/web`, `apps/bot`, `packages/shared`, `packages/db` | Общие Zod-схемы, типы БД, таблицы дропа и XTR-пакетов |
| Тесты | Vitest, Playwright, pgTAP, k6 | unit / e2e / RLS / нагрузка |
| CI/CD | GitHub Actions → Railway (Wait for CI), Supabase migrations в pre-deploy, Cloudflare Pages для SPA | Zero-downtime, миграции не в build-фазе |
| Регион | Railway `europe-west4-drams3a` (Амстердам), Supabase — ближайший EU | Пинг до СНГ/Telegram; замер на этапе 1 |

**Почему не «всё на Supabase Edge Functions»:** лимит CPU 2 с, 256 MB, cold starts, нет долгоживущего WebSocket-процесса, HTML только с custom domain. **Гибрид:** Railway = бот, вебхуки, воркеры, RNG-координация; Supabase = БД, RPC, RLS, Realtime, Storage, cron, лёгкие Edge Functions.

**Почему не Flutter Web:** исходник — Flutter/Dart AOT без исходного кода; перенос на Flutter Web дал бы огромный бандл, плохую производительность canvas в TMA и конфликт с Telegram JS API. React SPA точнее управляет DOM и веб-анимациями.

**Поток открытия кейса (обязательный):**
1. Клиент → `POST /cases/open` с `{case_id, count, client_seed, idempotency_key}`.
2. Railway валидирует JWT; вызывает `public.open_case(...)` RPC.
3. RPC: `SELECT … FROM wallets FOR UPDATE` → проверка баланса → `INSERT INTO bets ... ON CONFLICT DO NOTHING` → расход → HMAC-RNG по `server_seed:client_seed:nonce` → выбор предмета/wear/ST → `INSERT INTO inventory_items`, `rolls`, `transactions` → COMMIT.
4. Клиент получает **готовый результат** + `seed_hash`; проигрывает рулетку ровно до этого индекса.
5. Повтор с тем же `idempotency_key` возвращает сохранённый ролл без списания.

Диаграммы и последовательности — [`04-architecture.md`](04-architecture.md).

## 13. Безопасность, честность, анти-чит

Подробности — [`07-security.md`](07-security.md).

1. **Валидация `initData` (только сервер):**
   `secret_key = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN)`;
   `data_check_string = отсортированные key=value через \n` (без `hash`);
   `hash = hex(HMAC_SHA256(key=secret_key, msg=data_check_string))`;
   сравнение `timingSafeEqual`, проверка `auth_date` (≤ 3600 с), anti-replay по `query_id`.
   `initDataUnsafe` — **только для UI**. Передача initData только в `Authorization: tma ...`, никогда в URL/логи.
2. **JWT:** ES256 через Supabase JWT Signing Keys, `app_metadata.telegram_user_id`, короткий TTL + refresh. Клиенту — только `sb_publishable_...`; `service_role`/`sb_secret_...` и `BOT_TOKEN` — только в secrets Railway/Supabase.
3. **RLS + revoke grants + pgTAP-тесты** на все таблицы.
4. **Provably fair:** `server_seed = randomBytes(32)`, `sha256(server_seed)` публикуется до раунда; `digest = HMAC_SHA256(server_seed, "<client_seed>:<nonce>")`; первые 4 байта → `uint32 / 2^32`; результат/списание в одной транзакции; ротация сида с публичным reveal; экран «Проверить раунд» в Mini App.
5. **Запрещено:** `Math.random()` в игровой логике, клиентский расчёт дропа, любые «предсказания» на клиенте, передача результата от клиента.
6. **Анти-чит:** rate limiting, дедупликация `idempotency_key`, проверка серверного времени, сверка баланса триггерами, аудит `rolls`, алерты на аномальный RTP, бан по `telegram_user_id`, защита от_double-spend через `FOR UPDATE`.
7. **Платежи:** выдача товара **только** после `successful_payment`; `answerPreCheckoutQuery` ≤ 10 с; хранение `telegram_payment_charge_id`; обработка `refunded_payment` и `refundStarPayment`; `invoice_payload` ↔ `star_payments` ↔ `entitlements` связка.
8. **Веб:** CSP с `frame-ancestors` для Telegram-origin, только HTTPS, `Allow` только `telegram.org` скрипт + свой домен, без inline-скриптов, подпись каталога, валидация всех входящих через Zod.

## 14. Платежи в Telegram Stars (детальный флоу)

Полный прайс и таблицы — [`09-monetization.md`](09-monetization.md).

**Жёсткие правила (официальная документация Telegram):**
- Цифровые товары/услуги в Telegram — **только** `currency: "XTR"`, `provider_token: ""`, один `LabeledPrice` с целым `amount` в звёздах.

- Обязательны `/terms`, `/support`, `/paysupport`, оферта и согласие **до** покупки; тест — отдельный бот в test-окружении (`/test/METHOD_NAME`).

```
Клиент «КУПИТЬ ★N» → POST /payments/invoice {sku}
```

## 15. Онлайн и Realtime (D-02: без ботов)

| Канал Supabase Realtime | Тип | События |
|---|---|---|
| `chat:global` | Broadcast | новое сообщение, удаление, бан |
| `battle:<id>` | Broadcast + Postgres Changes | создание, join, `starting`, roll каждого слота, `settled` |
| `battle:lobby` | Postgres Changes | список активных лобби, фильтры |
| `jackpot:current` / `crash:current` | Broadcast | ставка, таймер, `crashedAt`, `spin`, результат |
| `user:<telegram_user_id>` | Postgres Changes (приватный, RLS) | баланс, инвентарь, entitlement, уведомление |
| `leaderboard:season` | Broadcast | обновление топа |

**Правила:**
- Broadcast — для всего массового (не нагружает авторизацией RLS на каждого подписчика); Postgres Changes — только персональные данные.
- RLS на `realtime.messages`; `realtime.broadcast_changes()` триггер для серверных событий; `replica identity full` для old-записей.
- Таймеры раундов считаются от **серверного времени** (`/time`), клиент не может ускорить/отменить раунд.
- Если живых соперников нет: `waitingForOpponent`, ставка **не списывается**; по таймауту — отмена с полным возвратом (D-02).
- Reconciliation при реконнекте: клиент запрашивает `/me` + состояние активного раунда и приводит UI к серверному состоянию.
- Heartbeat раз в N секунд; «онлайн» статус друзей = последний heartbeat < 60 с.

## 20. Требования к документации и `AGENTS.md` ⚠️ ОБЯЗАТЕЛЬНЫЙ РАЗДЕЛ

**Это требование включается в сам процесс разработки, а не только в текущий пакет файлов.**

1. **Корневой `AGENTS.md`** — не более **200 строк**, является единственной точкой входа для любого AI-агента и нового разработчика. Он обязан:
   - кратко описывать проект и цель 1:1;
   - содержать **ссылки на все файлы документации** (`docs/00-ТЗ.md` … `docs/14-open-questions.md`, `docs/decisions/*`, `docs/reference/*`);
   - задавать правила: «прочитай перед изменением кода», «не меняй экономику без ADR», «все деньги — сервер», «не коммить секреты», «обновляй changelog и bugs»;
   - определять формат коммитов, веток, PR, тестов.
2. **Вся документация лежит в отдельной папке `docs/`**, чтобы контекст не терялся. Корень репозитория содержит только `AGENTS.md`, `README.md`, конфиги и исходники.
3. **Обязательные файлы** (созданы в этом пакете, ведутся весь жизненный цикл):
   - `docs/04-architecture.md` — структура проекта/монорепо, дерево каталогов, назначение каждого пакета;
   - `docs/03-design-system.md` — оформление: палитра, шрифты, компоненты, отступы, анимации, эталонные скриншоты;
   - `docs/12-bugs-and-fixes.md` — **реестр багов**: ID, severity, шаги воспроизведения, expected/actual, статус, коммит-исправление, регресс-тест;
   - `docs/13-changelog.md` — журнал изменений;
   - `docs/decisions/ADR-*.md` — архитектурные решения с контекстом/последствиями;
   - `docs/14-open-questions.md` — вопросы заказчику и принятые ответы;
   - `docs/reference/` — неизменяемые снимки исходных данных и кадры.
4. **Правило обновления:** каждый PR, меняющий поведение, обязан обновить минимум один профильный doc + строку в `13-changelog.md`. Каждый найденный баг → строка в `12-bugs-and-fixes.md` **до** исправления, после — ссылка на коммит и тест. Каждое спорное решение → новый ADR.
5. **CI-проверка документации:** job `docs-lint` валидирует, что все ссылки в `AGENTS.md` и `00-ТЗ.md` резолвятся, `AGENTS.md` ≤ 200 строк, в changelog есть запись для текущего тега.
6. **Контекстные файлы для агентов:** `docs/reference/` не перезаписывается; `docs/01-reverse-engineering.md` фиксирует, откуда взяты факты, чтобы следующие сессии не переделывали разбор APK/видео.
7. **Язык документации:** русский; код, идентификаторы, конфиги — английский.

## 23. Тестирование и критерии приёмки

Полный тест-план — [`11-testing-qa.md`](11-testing-qa.md).

**Обязательные виды:** unit (RNG, формулы, цены), integration (RPC, транзакции), RLS/pgTAP, contract (Zod), e2e Playwright в Telegram WebApp-эмуляции, платёжный флоу в test-окружении, нагрузка k6 (500 юзеров, 50 openings/с), визуальные снапшоты против `reference/screenshots`, security checklist.

**Критерии приёмки (все должны выполняться):**
1. Сверка «экран в экран» по 40 состояниям из `02-ui-map.md`: различия только адаптивные, без пропущенных элементов/текстов.
2. Все 241 кейс открываются, дропают предмет с редкостью/wear/float/StatTrak и корректной ценой из снимка.
3. Все 22 `game_disabled_*` игры реализованы и играбельны; флаг отключает игру без деплоя.
4. PvP-битва между **двумя реальными** аккаунтами завершается с корректным расчётом и выдачей выигрыша; ботов нет.
5. Чат/друзья/подарки/рефералы работают между двумя реальными аккаунтами в реальном времени.
6. Покупка любого SKU за XTR в test-окружении: `pre_checkout_query` отвечает < 10 с, entitlement выдаётся один раз, повтор webhook не дублирует, `refundStarPayment` отзывает.
7. Ни один платёж не выдаёт товар без `successful_payment`; ни один `idempotency_key` не списывает средства дважды.
8. Provably-fair: игрок может проверить раунд, `sha256(server_seed)` совпадает с опубликованным.
9. p95 ролла ≤ 250 мс, 60 fps рулетки, NFR-01..NFR-17 выполнены.
10. Оферта, 18+, `/terms`, `/support`, `/paysupport`, дисклеймер «не реальные деньги» доступны из Mini App и бота.
11. Все doc-файлы из раздела 20 существуют, `AGENTS.md` ≤ 200 строк, `docs-lint` зелёный.
12. Нет секретов в репозитории, RLS включён на 100 % таблиц, security-аудит без критичных находок.
