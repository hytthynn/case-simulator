# ADR-004 · Онлайн: реальные игроки, без ботов

- **Дата:** 2026-11-06 · **Статус:** принято (решение D-02)
- **Связано:** [`06-api.md`](../06-api.md) §7/§11, [`05-database.md`](../05-database.md) §4, [`00-ТЗ.md`](../00-ТЗ.md) §15

## Контекст
В оригинале есть чат, друзья, рефералы, PvP-битвы кейсов, джекпот и Crash с общими ставками. Заказчик потребовал **настоящий онлайн и никаких ботов**. Это исключает типичное решение «подставить AI-соперника, если лобби пустое».

## Рассмотренные варианты
| Вариант | Вердикт |
|---|---|
| Серверная экономика + AI-соперники | ❌ прямо запрещено D-02 |
| Полный PvP + Postgres Changes на все события | ⚠️ деградация при >1000 подписчиков из-за RLS на каждое событие |
| **Broadcast для массового + Postgres Changes для персонального, реальные игроки** | ✅ |
| Peer-to-peer между клиентами | ❌ нет авторитетности, легко читерить |

## Решение
- Все участники `battle_players` — реальные `telegram_user_id`; таблица не допускает `is_bot`/синтетических ID (проверка в тесте ON-03).
- Лобби: `waiting` → при наборе нужного числа живых игроков → `starting` → **только в этот момент** списываются ставки. Таймаут → `cancelled` + полный возврат.
- Каналы Supabase Realtime:
  - **Broadcast:** `chat:global`, `battle:lobby`, `battle:<id>`, `jackpot:current`, `crash:current`.
  - **Postgres Changes (RLS, приватно):** `user:<id>` — баланс, инвентарь, entitlement, уведомления.
- Общие раунды Crash/Jackpot: состояние в `game_rounds`, таймеры от серверного времени, результат из заранее опубликованного `seed_hash`;Broadcast рассылается сервером (`.send()` с service key) или триггером `realtime.broadcast_changes()`.
- RLS на `realtime.messages`; `replica identity full` для old-записей.
- Reconciliation при реконнекте: `GET /me` + состояние активного раунда; клиент приводит UI к серверу.
- Heartbeat раз в N сек; «онлайн» друга = последний heartbeat < 60 с.

## Последствия
**Плюсы:** честный PvP, соответствует D-02, масштабируется, единый источник истины.
**Минусы:** на малой аудитории лобби могут пустовать → нужен UX ожидания, приглашения друзей, уведомления «соперник найден», разумный таймаут; нельзя «заполнить» лобби ради метрик.
**Открыто:** BUG-009 (UX пустого лобби), Q-08 (модерация чата), Q-13 (лидерборды), V-06 (p95 Realtime).
